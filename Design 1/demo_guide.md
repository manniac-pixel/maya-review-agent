# Maya Review Agent — Demo & Walkthrough Guide

> Step-by-step guide for presenting a live demo of the Maya Review Agent. Includes talking points, what to show, and how to narrate each section.

---

## Before the Demo

### Setup checklist

- [ ]  Python environment activated with all dependencies installed
- [ ]  `.env` file configured with Gemini API key (or Ollama running locally)
- [ ]  `data/raw_reviews.csv` and `data/gcash_reviews.csv` already scraped (use `--skip-scrape` to avoid live scraping delays)
- [ ]  Terminal window open with Rich-compatible font (for colored output)
- [ ]  `data/charts/` folder populated from a previous run
- [ ]  Browser tab open with `data/maya_insights_report.md` rendered (or Notion page)

### Timing

| Section | Duration | Cumulative |
| --- | --- | --- |

| Live Demo (pipeline run) | 3 min | 5 min |

## Part 1: Context & Problem (2 min)

### What to say

> "Maya is one of the top digital banks in the Philippines. But their app store ratings have been declining. We analyzed 12,345 reviews and found that users are leaving not because of missing features — but because of broken trust."

### Key stats to mention

- 12,345 reviews analyzed (Aug 2025 – Feb 2026)
- 4 of the top 5 issues have severity 5/5
- All top issues are trust-related: login failures, stolen funds, unreachable support
- Users explicitly mention switching to GCash

### User quotes to read aloud (pick 2)

> "I've tried several times today, but I can't get in."

> "My phone was stolen and the hacker was able to access this app and took my savings and made loan in a snap of a finger."

> "I tried calling your toll-free hotline, but no one answered."

> "The screen showed that it was successful, but the money never reflected on my balance until more than a day later."

### Transition

> "Reading 12,000 reviews manually would take weeks. So I built an AI agent to do it in minutes."

## Part 2: Live Demo — Running the Pipeline (3 min)

### What to show

Open terminal and run:

```bash
python main.py --skip-scrape --stars 1,2 --verbose
```

### Flags explained (say this while it loads)

| Flag | What it does |
| --- | --- |
| `--skip-scrape` | Uses cached reviews instead of live scraping (saves 5 min) |
| `--stars 1,2` | Filters to only 1 and 2-star reviews (the signal) |
| `--verbose` | Shows detailed logging so the audience can see each step |

### What the audience sees

1. **Rich progress bar** with 8 labeled steps
2. **Colored log output** showing what's happening at each step
3. **Completion banner** — green panel with all output file paths and runtime

### Talking points during the run

> "Step 1 loads the cached reviews — 10,000 Maya and 10,000 GCash."

> "Step 2 is temporal analysis — tracking how each issue evolves month over month. This is how we spotted that customer service complaints are getting *worse*, not better."

> "Step 3 is the heavy lift — Gemini 2.0 Flash reads every review and categorizes it by issue type, user journey, and severity."

> "Steps 4 and 5 map drop-offs to specific screens and flag accessibility gaps."

> "Step 6 compares Maya against GCash — so we know where users are actually switching."

> "Step 8 synthesizes everything into a single ranked report with auto-generated charts."

### If the pipeline is too slow for a live demo

Use pre-generated outputs and just show the command + completion banner:

```bash
# Show the command
echo "python main.py --skip-scrape --stars 1,2"

# Then open the pre-generated report
open data/maya_insights_report.md
```

## Part 5: Q&A Prep (2 min)

### Anticipated questions and answers

**Q: Why not just use App Store Connect analytics?**
> App Store Connect gives you ratings and review counts, but it doesn't categorize issues, rank them, map them to screens, or compare against competitors. The agent does all of that automatically.

**Q: How accurate is the LLM categorization?**
> We use Gemini 2.0 Flash which is optimized for classification tasks. For 1-star reviews, the signal is strong — users are very specific about what went wrong. The agent cross-references multiple reviews to validate patterns.

**Q: Could this work for other apps?**
> Yes. The pipeline is parameterized. You'd change the app ID in the config, adjust the analysis prompts for the domain, and run the same pipeline. The scraping, temporal analysis, and chart generation are fully generic.

**Q: Why Gemini instead of GPT-4?**
> Speed and cost. Processing 12K reviews with GPT-4 would be slower and more expensive. Gemini 2.0 Flash handles classification at scale very well. We also support Ollama as a free local alternative.

**Q: How long does a full run take?**
> Scraping takes ~5 minutes (rate-limited by the app stores). Analysis takes ~10 minutes with Gemini. Total: about 15 minutes for 20,000 reviews. With `--skip-scrape`, just the analysis takes ~8 minutes.

**Q: What would you do differently next time?**
> Two things: (1) Add App Store review scraping for iOS — right now iOS is less covered than Android. (2) Build a web dashboard instead of markdown reports, so stakeholders can explore the data interactively.
